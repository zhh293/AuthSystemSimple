# Design: Pluggable Directory Credential Verification

`IdentityServiceProvider` delegates only the username/password decision to `CredentialAuthenticator`. The default `JdbcCredentialAuthenticator` uses the existing Argon2id hash and a precomputed dummy hash for unknown users. When `sso.identity.credential-mode=directory`, `DubboDirectoryCredentialAuthenticator` invokes `DirectoryCredentialService` from `sso-contracts`; it does not access local password hashes.

After either verifier succeeds, the SSO provider still requires a local username mapping and checks its enabled state before creating a TGC. The local row remains the source of the stable SSO subject and profile. The external provider receives a password only in the request DTO over Dubbo; its `toString()` is redacted. Directory mode is accepted only with the `prod` or `production` profile, which enables Dubbo Triple mTLS; unknown or differently cased mode values fail startup validation. Production selects directory mode explicitly and protects the provider link with Dubbo Triple mTLS and Nacos service discovery. A generic account-change pull contract, transactional consumer, and freshness fail-closed policy are specified in [`SDD 011`](../011-directory-account-sync-rpc/spec.md); the organization still owns its provider implementation, field mapping, and live acceptance.
