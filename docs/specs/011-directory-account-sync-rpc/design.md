# Design: Directory Account Synchronization

The corporate directory implements `DirectoryAccountSyncService` as a Dubbo provider in Nacos. The SSO consumer polls one bounded page at a time. The opaque source cursor is stored in `sso_directory_sync_state`; cursor compare-and-set, account mapping changes, the successful-sync timestamp, and one batch audit record commit in the same MySQL transaction.

SSO instances may fetch the same page concurrently. The first transaction that matches the stored cursor applies the page. A stale worker whose expected cursor no longer matches rolls back the entire page and retries on the next scheduled run. Stable subject and normalized username are both unique; the synchronizer locks existing rows and refuses cross-account reassignment. A disabled-account update revokes all refresh-token families for that subject in the same transaction, so a later re-enable cannot reactivate previously issued tokens.

`sso.identity.directory-sync-max-staleness-seconds` defaults to 120 seconds. Directory-mode checks of account enabled status also require a recent successful sync. A missing/expired freshness timestamp raises a dependency-unavailable result rather than pretending the account is disabled: login and TGC checks return an unavailable response, OIDC UserInfo returns HTTP 503, and opaque-token introspection propagates the dependency failure so resource services return 503. This fails closed while preserving the TGC record for recovery. Database credential mode bypasses this freshness requirement.

The provider contract and consumer do not encode passwords or carry an operator-controlled actor field. Batch audit events use a fixed event type and correlation ID, and metrics use only a fixed outcome label. Operational failure logs include only a fixed outcome and, for unexpected failures, the exception class; they omit exception messages, payloads, account fields, and cursors. The external provider's identity mapping, cursor semantics, directory query, network policy, and mTLS certificate remain deployment-owned.
