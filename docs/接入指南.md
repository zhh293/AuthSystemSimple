# SSO 接入指南

本文说明如何把 Spring Boot RP（Relying Party，依赖方）接入认证中心。优先推荐使用 `sso-client-spring-boot-starter`；仓库中的 `sso-example-rp` 也保留标准 Spring Security OAuth2 Client 示例，便于对照迁移。

## 1. 注册 OAuth 客户端

先构建运维 CLI，并使用有权限的运维环境连接认证中心数据库。客户端 Redirect URI 必须与应用配置逐字一致，包含 scheme、host、port、path。开发环境允许 localhost HTTP；生产必须使用 HTTPS。

```powershell
mvn -pl sso-admin -am package
$env:SSO_DB_URL = 'jdbc:mysql://db.example/sso?sslMode=VERIFY_IDENTITY'
$env:SSO_DB_USERNAME = '<从密钥管理服务注入>'
$env:SSO_DB_PASSWORD = '<从密钥管理服务注入>'
$env:SSO_ADMIN_ACTOR = 'operator-name'
java -jar sso-admin/target/sso-admin-0.1.0-SNAPSHOT.jar client create `
  --id portal --name 'Internal Portal' --type CONFIDENTIAL `
  --redirect-uri https://portal.example.com/sso/callback `
  --scope openid --scope profile
```

生成的客户端 Secret 只显示一次，立即保存到应用的密钥管理服务。不要把 Secret 放进代码仓库、镜像层或日志。`PUBLIC` 客户端没有 Secret，必须使用 PKCE。CLI 更多说明见 [用户和客户端管理](specs/005-provisioning-cli/usage.md)。

## 2. 引入 Starter

在 Spring Boot 3.5.x、Java 17 应用中添加与本仓库发布版本一致的依赖：

```xml
<dependency>
  <groupId>com.authsystem</groupId>
  <artifactId>sso-client-spring-boot-starter</artifactId>
  <version>${sso.version}</version>
</dependency>
```

如尚未发布到 Maven 仓库，可在仓库根目录先执行 `mvn -pl sso-client-spring-boot-starter -am install`，再由示例应用或本地应用引用。Starter 为显式启用：未设置 `sso.client.enabled=true` 时不会注册 SDK 路由或过滤器。

## 3. 配置 RP

生产环境建议使用 Redis，以支持多实例共享授权事务、会话映射和刷新协调。SDK 的 family lifetime 默认是 30 天；认证中心的 refresh-token lifetime 默认也是 30 天。两端应明确设为相同值，并与认证中心的 `SSO_REFRESH_TOKEN_TTL_SECONDS` 对齐。

```yaml
sso:
  client:
    enabled: true
    issuer: https://sso.example.com
    client-id: portal
    client-secret: ${SSO_CLIENT_SECRET}
    redirect-uri: https://portal.example.com/sso/callback
    scopes: [openid, profile]
    family-lifetime: 30d
    local-store: false
    redis-key-prefix: sso:rp:production
    lookup-hmac-key: ${SSO_CLIENT_LOOKUP_HMAC_KEY}
    refresh-encryption-key: ${SSO_CLIENT_REFRESH_AES_KEY}
    secure-cookie: true
    cookie-same-site: Lax
    protected-paths: [/app/**, /api/**]
    public-paths: [/, /error, /assets/**]
    user-mapping-cache-ttl: 250ms # 可选 Caffeine L1 缓存；最大 1 秒，0 表示禁用
```

`lookup-hmac-key` 与 `refresh-encryption-key` 都必须是 Base64 编码的 32 字节密钥，并从密钥管理服务注入。Redis 连接信息由 Spring Data Redis 配置提供；生产必须配置 TLS、认证、私网访问和连接超时。Redis 故障时 SDK 会 fail closed，不会切换到本地存储。

区分两种“本地”能力：`local-store: true` 会使用进程内 `ConcurrentHashMap` 保存授权状态、令牌映射和刷新锁，仅供单实例开发；它**不是 Caffeine，也不适用于生产或多实例**。`user-mapping-cache-ttl` 配置的是 Redis Store 上的可选 Caffeine L1 查询缓存，不替代 Redis 持久/共享存储。

## 4. 接入 Spring Security

把 SDK Configurer 加到应用已有的 `SecurityFilterChain`，并在最终 `anyRequest` 规则之前配置：

```java
@Bean
SecurityFilterChain applicationSecurity(
        HttpSecurity http,
        SsoHttpSecurityConfigurer sso) throws Exception {
    http.with(sso, Customizer.withDefaults())
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/", "/error", "/assets/**").permitAll()
            .anyRequest().authenticated());
    return http.build();
}
```

应用仍负责自己的授权规则、CSRF 策略和公开路由。SDK 仅放行它自己的登录、回调 GET 和退出 POST 路由。保持 CSRF 开启；退出表单必须提交 Spring Security CSRF token。若主应用关闭 CSRF，SDK 退出端点会返回 403。

SDK 登录成功后将 `SsoAuthentication` 放入请求 SecurityContext，可通过 `SsoCurrentUser.get()` 读取已验证的最小化 `SsoPrincipal`。浏览器只会收到 `{client-id}_access_token` Cookie；Refresh Token 和 ID Token 保存在应用后端，不会发给浏览器。当 Access Token 过期时，SDK 会尝试用 Refresh Token 续期；若 Refresh Token 也过期、被撤销或刷新失败，SDK 会清除应用自己的会话映射和 Access Token Cookie，然后按页面/API 类型处理本次请求。API 默认返回 401（JSON `authentication_required`），前端可在收到 401 后以顶层页面导航的方式访问 SDK 登录入口 `GET /sso/login`，可携带经服务端安全处理的站内 `returnTo`，登录完成后再重试原请求。页面请求则由 SDK 自动跳转到该入口。重新进入 SSO 时，若认证中心的 TGC 仍有效，通常可免交互签发新令牌；本地刷新失败不会删除认证中心的 TGC。`/sso/status` 默认关闭，确有需要时再启用。

## 5. 示例应用

仓库的 SDK 示例 Profile 使用 localhost HTTP 和单实例内存 Store，仅供开发演示：

```powershell
$env:SPRING_PROFILES_ACTIVE = 'sso-sdk'
$env:SSO_CLIENT_ID = 'portal'
$env:SSO_CLIENT_SECRET = '<本地密钥管理服务中的 Secret>'
mvn -pl sso-example-rp -am spring-boot:run
```

应用监听 `http://localhost:8082`，访问 `/profile` 测试受保护页面。此 Profile 的本地状态在进程重启后丢失，不可用于生产。常规 OAuth2 Login 示例默认监听 `8090`，详见根目录 [README](../README.md)。

## 6. 生产验收清单

- Redirect URI、issuer、客户端类型和授权 scope 已核对；RP 与认证中心时钟同步。
- 浏览器 Cookie 使用 Secure、HttpOnly，并按站点拓扑设置 SameSite；公网入口使用 HTTPS。
- 多实例使用 Redis Store；验证 Redis 断连时失败关闭、刷新并发协调和 Redis 恢复行为。
- 验证回调 state/nonce/PKCE、登录取消、无效 code、访问令牌刷新、family 到期、退出及 CSRF。
- 确认认证码、state、令牌、Authorization Header、密码和用户数据均不会进入应用日志或指标标签；反向代理及访问日志需清除回调查询参数。
- 验证 API 未登录返回 401、用户信息字段最小化、RP 本地退出行为符合预期。RP 本地退出不等于清除认证中心 TGC 全局会话。

更多参数和迁移限制见 [SDK 配置与迁移文档](specs/012-sso-client-sdk/usage.md)。
