# SSO 认证中心部署指南

本文包含本地开发部署及生产环境部署准备。生产部署必须根据组织的安全基线配置网络、证书、数据库高可用、备份、密钥管理和告警；本文不能替代这些环境级设计。仓库内 Compose 只供本机开发。

## 1. 本地开发环境

### 依赖与启动

安装 Java 17+、Maven 3.9+ 和 Docker Compose。在仓库根目录执行：

```powershell
docker compose up -d
docker compose ps
mvn -pl sso-server -am package
```

Compose 提供 MySQL 8.4、Redis 7.4 和单机 Nacos 2.4.3。默认端口分别为 `3306`、`6379`、`8848`/`9848`。示例凭据和 Nacos 配置均为开发用途，禁止暴露到公网或复用于生产。首次认证服务启动由 Flyway 自动应用 `sso-server/src/main/resources/db/migration` 中的迁移。

启动认证中心：

```powershell
$env:SSO_COOKIE_SECURE = 'false' # 只限 localhost HTTP
$env:SSO_ISSUER = 'http://localhost:8080'
mvn -pl sso-server -am spring-boot:run
```

也可以先构建可执行包，再启动：

```powershell
mvn -pl sso-server -am package
java -jar sso-server/target/sso-server-0.1.0-SNAPSHOT.jar
```

管理端点默认绑定 `127.0.0.1:8081`，健康检查地址为 `http://127.0.0.1:8081/actuator/health`。认证 HTTP 监听 `8080`，Dubbo Triple 默认监听 `50051`。若本机之前配置了不同数据库密码，请通过 `SSO_DB_URL`、`SSO_DB_USERNAME`、`SSO_DB_PASSWORD` 与实际 MySQL 配置对齐；不要为了测试随意修改已有数据库用户或密码。

### 初始化用户和客户端

Flyway 迁移只创建结构，不会自动创建登录用户和 OAuth 客户端。先构建 CLI：

```powershell
mvn -pl sso-admin -am package
$env:SSO_DB_URL = 'jdbc:mysql://localhost:3306/sso?useUnicode=true&characterEncoding=utf8'
$env:SSO_DB_USERNAME = 'sso'
$env:SSO_DB_PASSWORD = 'sso-local-password'
$env:SSO_ADMIN_ACTOR = 'local-operator'
```

交互式创建用户（密码在提示时输入，不要作为命令行参数）：

```powershell
java -jar sso-admin/target/sso-admin-0.1.0-SNAPSHOT.jar user create `
  --username alice --subject user-123 --display-name 'Alice Chen' --email alice@example.com
```

注册本地示例 RP：

```powershell
java -jar sso-admin/target/sso-admin-0.1.0-SNAPSHOT.jar client create `
  --id example-rp --name 'Example RP' --type CONFIDENTIAL `
  --redirect-uri http://localhost:8090/login/oauth2/code/sso `
  --scope openid --scope profile --scope email --scope resource.read
```

客户端 Secret 只显示一次，保存到本地安全的 Secret Store。运行普通 OAuth2 RP 示例：

```powershell
$env:SSO_RP_CLIENT_ID = 'example-rp'
$env:SSO_RP_CLIENT_SECRET = '<上一步显示的 Secret>'
$env:SSO_ISSUER = 'http://localhost:8080'
mvn -pl sso-example-rp -am spring-boot:run
```

访问 `http://localhost:8090`。SDK Profile 示例和生产接入参数见[接入指南](接入指南.md)。

## 2. 生产拓扑与前置条件

生产环境至少需要：

- SSO Server 多实例部署在受控私网，HTTP 入口由 TLS 反向代理或负载均衡保护；节点间时间同步。
- MySQL 使用高可用方案、备份及恢复演练；JDBC URL 使用 `sslMode=VERIFY_IDENTITY`。
- Redis 启用 TLS、认证和持久/高可用策略；SSO 服务使用 Redis 进行分布式登录限流。
- Nacos 使用认证、TLS 和证书校验；禁止使用 Compose 中关闭认证/TLS 的 Nacos 配置。
- Dubbo Triple 使用双向 TLS，准备服务端证书、私钥、受信客户端 CA，以及客户端证书、私钥和受信服务端 CA。
- 由 Secret Manager 注入数据库、Redis、Nacos 和 HMAC 密钥；PKCS#12 OIDC 签名密钥通过安全文件挂载提供。
- 健康检查、指标采集、告警、审计日志、访问日志脱敏和密钥轮换操作已通过环境验收。

## 3. 生产配置

使用 `prod` Profile 启动认证中心。生产 Profile 对数据库、Redis、Nacos、身份认证模式、issuer、签名密钥、HMAC 密钥和 Dubbo TLS 文件使用显式配置；启动前应将所需值注入进程环境。主要变量如下：

| 变量 | 用途 |
| --- | --- |
| `SPRING_PROFILES_ACTIVE` | 设置为 `prod`。 |
| `SSO_ISSUER` | 对外公开的 HTTPS issuer，所有 RP 必须使用同一值。 |
| `SSO_DB_URL`、`SSO_DB_USERNAME`、`SSO_DB_PASSWORD` | MySQL 地址和凭据；URL 应设置 `sslMode=VERIFY_IDENTITY`。 |
| `SSO_REDIS_HOST`、`SSO_REDIS_PORT`、`SSO_REDIS_PASSWORD` | Redis 地址和凭据；生产 Profile 已开启 Redis TLS。 |
| `NACOS_ADDRESS`、`NACOS_NAMESPACE`、`NACOS_USERNAME`、`NACOS_PASSWORD` | 受 TLS 保护的 Nacos 注册中心和凭据。 |
| `SSO_IDENTITY_CREDENTIAL_MODE` | `database` 或 `directory`。目录模式必须部署对应的认证和账号同步 RPC Provider。 |
| `SSO_SESSION_HMAC_KEY`、`SSO_RATE_LIMIT_HMAC_KEY`、`SSO_OAUTH_STATE_HMAC_KEY`、`SSO_TOKEN_STORAGE_HMAC_KEY` | 独立随机密钥；每个至少 32 UTF-8 字节，由 Secret Manager 提供。 |
| `SSO_OIDC_KEYSTORE_PATH`、`SSO_OIDC_KEYSTORE_PASSWORD`、`SSO_OIDC_KEY_ALIAS` | 外部 PKCS#12 RSA 签名密钥及 alias。 |
| `SSO_AUTH_STORAGE_ENCRYPTED` | 需加密授权存储时设为 `true`；启用前确认各节点密钥配置一致。 |
| `SSO_DUBBO_SERVER_CERT`、`SSO_DUBBO_SERVER_KEY`、`SSO_DUBBO_CLIENT_CA` | Triple Provider 服务端证书、私钥和客户端信任 CA。 |
| `SSO_DUBBO_CLIENT_CERT`、`SSO_DUBBO_CLIENT_KEY`、`SSO_DUBBO_SERVER_CA` | 服务间 Triple 调用的客户端证书、私钥和服务端信任 CA。 |

按 Nacos 版本要求通过 `JAVA_TOOL_OPTIONS` 配置客户端 RPC TLS，并确保服务端启用了 TLS 和证书校验：

```text
-Dnacos.remote.client.rpc.tls.enable=true
-Dnacos.remote.client.rpc.tls.trustAll=false
-Dnacos.remote.client.rpc.tls.trustCollectionChainPath=/run/secrets/nacos-ca.pem
```

生产启动示例：

```powershell
$env:SPRING_PROFILES_ACTIVE = 'prod'
java -jar sso-server/target/sso-server-0.1.0-SNAPSHOT.jar
```

`application-prod.yml` 与生产配置校验代码是配置基线；部署系统还需限制只开放必要端口。不要将管理端口 `8081` 暴露到公网。若要让 Prometheus 采集跨主机指标，配置 `SSO_MANAGEMENT_ADDRESS` 绑定专用管理网卡，并使用网络 ACL 或认证代理限制访问。

## 4. 数据迁移和账号准备

首次发布或升级时，先备份数据库并评估对应 Flyway 迁移，再通过受控变更窗口启动服务完成迁移。生产凭据不可用时不要跳过迁移或手工伪造 `flyway_schema_history`。

运维 CLI 可在受控运维机上运行，直接访问数据库但不会启动 HTTP、Dubbo 或连接 Nacos。设置 `SSO_DB_URL`、`SSO_DB_USERNAME`、`SSO_DB_PASSWORD`、`SSO_ADMIN_ACTOR` 后按[CLI 指南](specs/005-provisioning-cli/usage.md)创建用户和客户端。用户密码由 CLI 交互输入并使用 Argon2id 编码；不要通过 shell history、流水线日志或工单传递密码。目录账号应先通过 `user link-directory` 建立稳定 subject 映射。

注册每个 RP 时，核实精确的 HTTPS Redirect URI、客户端类型、最小 scope 和客户端 Secret 保存位置。向资源服务发令牌的客户端需申请 `resource.read`，资源服务还会单独校验客户端 allowlist。

## 5. RP 和资源服务

生产 RP 应按[接入指南](接入指南.md)配置 `local-store: false`、Redis TLS、唯一 `redis-key-prefix` 和与 SSO 一致的 family lifetime。SDK 的 Caffeine L1 查询缓存可选，TTL 最长 1 秒；它不替代 Redis。SDK 本地内存 Store 仅适用于单实例开发。

资源服务生产 Profile 需要 `SSO_RESOURCE_ALLOWED_CLIENT_IDS`、Dubbo 客户端证书及 Nacos TLS 配置。HTTP 入口也必须使用 TLS，并确保访问日志不记录 `Authorization` Header。示例服务使用 `/api/whoami` 说明调用方式，详见[资源服务指南](specs/009-resource-token-rpc/usage.md)。

## 6. 部署后检查

1. 检查 `GET /actuator/health`（仅管理网络可达）和服务日志中的 Flyway、数据库、Redis、Nacos、Dubbo TLS 初始化结果。
2. 确认 OIDC Discovery 中 issuer 与公开 HTTPS 域名完全一致，JWKS 能返回当前公钥，服务端时间同步正常。
3. 用测试客户端完成授权码 + PKCE 登录、令牌刷新和退出，确认错误 Redirect URI 被拒绝，CSRF 缺失的退出请求被拒绝。
4. 以资源服务测试令牌校验：有效 token 可通过；过期、撤销、错误 scope/client 应拒绝；SSO RPC 不可用时返回服务不可用并 fail closed。
5. 验证 Redis、MySQL、Nacos 故障演练及多实例刷新/退出行为；确认管理端口未对公网开放。
6. 检查应用、代理、Dubbo、Nacos、数据库和 Prometheus 日志/标签未泄漏密码、客户端 Secret、Cookie、授权码、Access/Refresh/ID Token 或个人数据。

## 7. 当前验证范围

当前仓库可确认的验证结果：SDK Core 36 项与 Starter 22 项单元测试通过；`sso-server` Maven package 成功。服务端没有测试源码。本机启动冒烟检查已进入 Spring Boot 应用初始化，但因 MySQL 拒绝默认 `sso` 凭据，在 Flyway 连接阶段退出。当前环境没有可用 Redis、Docker/Nacos 拓扑及生产证书，因此尚未完成认证中心 HTTP 健康检查、真实 OIDC 登录、跨服务 Dubbo 调用或全链路故障演练。生产上线前必须在与目标拓扑相同的测试环境执行上述检查。

密钥轮换、OIDC 签名 Key 轮换和监控告警示例见根目录 [README](../README.md)、[运维监控说明](../ops/monitoring/README.md)及对应的 `docs/specs` 文档。
